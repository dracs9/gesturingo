## 1. Контекст

Проект для ADMIT Hackathon 2026, кейс «Motion: камера вместо джойстика».

**Задача кейса:** веб-приложение, которым можно управлять движениями тела, рук или лица
через обычную веб-камеру, без клавиатуры и мыши.

**Наш продукт:** приложение, в котором руками управляется ВСЁ — и навигация, и обучение.
Человек без знания жестового языка открывает ссылку, за 30 секунд учится управлять
интерфейсом жестами, затем учит буквы русской дактильной азбуки по «призрачной руке» на
экране. Камера замечает неточности и даёт конкретную подсказку («согни безымянный палец»).
Выученные буквы он сразу использует в режиме «Мост»: жесты превращаются в текст и голос.

**Аудитория:** слышащие, которые хотят общаться с глухими — родители глухих детей,
родственники, педагоги, работники сферы услуг. Жюри не знает жестового языка — приложение
обязано быть понятным без подготовки.

**Сроки:** сдача 30.09 15:00 (Астана, UTC+5). Жюри открывает ссылку и проходит сценарий
само. Если проект не запустится — 0 баллов за работоспособность. Надёжность важнее фич.

## 2. Требования кейса и критерии

Обязательный минимум:
- распознавание движений в реальном времени, в браузере, без установки;
- минимум 3 разных жеста, каждый вызывает своё действие;
- понятная визуальная обратная связь (пользователь видит, что система его «видит»);
- законченный сценарий: начало → процесс → результат;
- ТВИСТ, режим «ошибка»: замечать неправильное движение и давать КОНКРЕТНУЮ подсказку.

Критерии (100 баллов): работоспособность 30, режим «ошибка» 20, техническая реализация 20,
UX/дизайн 15, оригинальность 10, бонусы 5.

Бонусы: собственная логика распознавания, прогресс/рекорды, адаптация под телефон,
звук и эффекты.

Правила: готовые библиотеки (MediaPipe) можно; основная логика пишется после 28.09 07:00;
жюри проверяет историю коммитов; все сторонние ресурсы указываются в README.

## 3. Концепция: три слоя жестов

| Слой | Назначение | Жесты | Нужно ли знать ЖЯ |
|---|---|---|---|
| 1. Управление | Навигация по всему приложению | курсор-палец, щипок (клик), клик задержкой, большой палец вверх (ОК), открытая ладонь (назад) | Нет |
| 2. Содержание | То, что учим | буквы русской дактильной азбуки (статичные) | Нет: образец + призрачная рука + подсказки |
| 3. Мост | Применение выученного | буквы → слово → текст + озвучка | Нет, только выученное |

Мышь допустима только для одного действия — разрешения камеры на первом экране.
Кнопки мышью оставить как запасной вариант, но весь сценарий проходится руками.

## 4. Стек и ограничения

- React 18 + TypeScript (strict) + Vite
- `@mediapipe/tasks-vision` — HandLandmarker, режим VIDEO, `numHands: 1`,
  GPU delegate с фолбэком на CPU; wasm и модель — с CDN, пути вынести в конфиг
- Canvas 2D поверх `<video>` — скелет, призрачная рука, курсор, кольца прогресса
- Zustand — состояние; localStorage — прогресс (обернуть в try/catch)
- Web Speech API `speechSynthesis` — озвучка в режиме «Мост» (голос `ru-RU`, если есть)
- Vitest — юнит-тесты модуля распознавания
- Стили: CSS-модули (или Tailwind — один выбор на весь проект)
- Деплой: Vercel (HTTPS обязателен для камеры)

**Бэкенда нет.** Никаких серверов, API, аккаунтов, регистрации, аналитики.
Видео и точки рук не покидают браузер — это часть ценности продукта.

Новые npm-зависимости — только с обоснованием и после моего согласия.

## 6. Конвейер распознавания

1. **Захват:** `getUserMedia({ video: { facingMode: "user", width: 640, height: 480 } })`,
   на телефоне — меньше. Видео отражено зеркально для пользователя.
2. **HandLandmarker** → 21 точка (x, y, z) + handedness + score.
3. **Проверки кадра** (`frameChecks`): рука найдена, score выше порога, все точки внутри
   кадра с отступом, размер ладони в допустимом диапазоне.
4. **Нормализация:** вычесть точку 0 (запястье); разделить на |0→9| (запястье → основание
   среднего пальца); повернуть так, чтобы вектор 0→9 смотрел вверх; для левой руки отразить по X.
5. **Признаки:** для каждого пальца углы в суставах (MCP, PIP, DIP; для большого — CMC, MCP, IP),
   состояние пальца `straight | half | bent`, расстояния между кончиками, положение большого
   пальца относительно ладони, нормаль ладони (к камере / боком / от камеры).
6. **Сглаживание:** EMA по точкам; решение о букве — большинством за последние ~8 кадров.
7. **Дальше** — слой управления (раздел 7) или слой букв (раздел 8), в зависимости от экрана.

Стартовые пороги (все в `thresholds.ts`): палец прямой при угле > 160°, согнут при < 100°,
между ними — полусогнут. Пороги подбираются по реальным данным.

## 7. Слой управления

### 7.1 Курсор-палец
- Позиция курсора = кончик указательного пальца (точка 8).
- Рабочая зона — центральные ~70% кадра маппятся на весь экран, чтобы до краёв экрана
  было легко дотянуться.
- Сглаживание — One Euro filter (или EMA): курсор не должен дрожать, но и не отставать.
- Курсор рисуется поверх интерфейса: круг ~24 px, при наведении на кнопку — увеличивается.
- Если рука пропала — курсор плавно гаснет через 0,5 с.

### 7.2 Щипок = клик
- Расстояние между точками 4 и 8, делённое на размер ладони.
- Гистерезис: «сомкнут» при < 0,35, «разомкнут» при > 0,50 (подобрать).
- Клик срабатывает на переходе «разомкнут → сомкнут», следующий клик — только после
  размыкания. Минимальный интервал между кликами 400 мс.
- Позиция клика — позиция курсора за ~100 мс ДО смыкания (при щипке палец смещается).

### 7.3 Клик задержкой (запасной)
- Курсор над кнопкой ≥ 1 с → клик. Вокруг курсора заполняется кольцо.
- Работает всегда параллельно щипку — для тех, у кого щипок не выходит.

### 7.4 Позы-команды
| Поза | Удержание | Действие |
|---|---|---|
| Большой палец вверх | 0,8 с | ОК / подтвердить / далее |
| Открытая ладонь к камере | 1,5 с | назад / выход из урока |

У каждой позы — кольцо прогресса удержания на экране.

### 7.5 Контекст жестов (защита от столкновений)
Буква может случайно сработать как команда. Поэтому активные жесты зависят от экрана
(`gestureContext.ts`):

| Экран | Курсор + щипок + задержка | ОК (палец вверх) | Назад (ладонь 1,5 с) | Буквы |
|---|---|---|---|---|
| Welcome, LevelMap, Results | да | да | да | нет |
| ControlTutorial | только тренируемый жест | по шагу | по шагу | нет |
| Lesson | НЕТ | нет | да | только текущая буква |
| Bridge | нет | нет | да | все выученные |
| Record | да (кнопки) | нет | да | нет |

На экранах Lesson и Bridge буква, похожая на ладонь, не должна давать «назад»:
«назад» требует 1,5 с удержания — дольше, чем засчитывание буквы (1 с).

### 7.6 UI под жесты
- Кнопки не меньше 100–120 px, не больше 3–4 на экране, с отступами.
- Каждая кнопка (`GestureButton`) подсвечивается при наведении и показывает кольцо задержки.
- В углу всегда `GestureLegend` — 4 иконки жестов управления с подписями.
- `HandStatus` всегда виден: «Руки не видно», «Слишком далеко», «Слишком близко»,
  «Вижу руку ✓».

## 8. Слой содержания: буквы

### 8.1 Спецификация буквы
```ts
type FingerState = "straight" | "half" | "bent";
type Finger = "thumb" | "index" | "middle" | "ring" | "pinky";

interface LetterSpec {
  letter: string;              // "А"
  verified: boolean;           // true только после сверки с официальной таблицей
  fingers: Partial<Record<Finger, { state: FingerState; hintCode: string }>>;
  extra?: Array<
    | { type: "tipsTouch"; a: Finger; b: Finger; hintCode: string }
    | { type: "tipsApart"; a: Finger; b: Finger; hintCode: string }
    | { type: "palmFacing"; value: "camera" | "side" | "away"; hintCode: string }
    | { type: "thumbPosition"; value: "acrossPalm" | "side" | "up"; hintCode: string }
  >;
  confusedWith?: string[];     // похожие буквы
  reference: string;           // путь к эталону для призрачной руки
}
```

**ВАЖНО: не придумывай формы букв.** Команда заполнит `letters.ts` по официальной таблице
русской дактильной азбуки. Ты создаёшь инфраструктуру и 2–3 буквы-заглушки с
`verified: false` и комментарием `// TODO: сверить с официальной таблицей`.
Буквы с движением (Й, Щ, Ё и др.) в MVP не входят.

### 8.2 Классификация
- Основа — правила: для текущей буквы проверяются все условия спецификации, каждое
  нарушение даёт ошибку `{ code, finger?, severity, hintCode, landmarkIds }`.
- kNN (k=5, 63 признака = 21 точка × 3 после нормализации, евклидово расстояние) —
  второй слой: различает буквы из `confusedWith` и повышает уверенность.
- Буква засчитывается, когда правила выполнены И (если есть образцы) kNN согласен,
  и это состояние держится ≥ 1 с. Под буквой — кольцо прогресса удержания.

### 8.3 Призрачная рука (`ghost.ts`, `GhostHand`)
- Эталон буквы — один чистый кадр нормализованных точек из `references/<буква>.json`.
- Эталон подгоняется под руку пользователя: перенос в его запястье, масштаб по его размеру
  ладони, поворот по его вектору 0→9. Рисуется полупрозрачным скелетом поверх руки.
- Каждый палец сравнивается с эталоном: совпал — зелёный, не совпал — красный,
  палец из текущей подсказки — пульсирует.
- Если эталона нет — показывается только карточка-образец (картинка/схема).

## 9. Режим «ошибка»

### 9.1 Уровни
| Уровень | Что проверяем | Пример подсказки |
|---|---|---|
| Кадр | рука есть, целиком в кадре, расстояние, уверенность трекинга | «Рука слишком далеко — подойди ближе» |
| Управление | щипок, позы-команды | «Щипок не засчитан — соедини кончики пальцев ближе» / «Поверни ладонь к камере» |
| Путаница | показана буква из `confusedWith` | «Похоже на О — раскрой кольцо шире» |
| Форма буквы | нарушенные условия спецификации | «Согни безымянный палец» / «Прижми большой палец к ладони» |

Проверки идут сверху вниз: если есть ошибка кадра, ошибки формы не показываем.

### 9.2 Поведение подсказок (`hintEngine.ts`)
- Показывается ОДНА подсказка — самая важная (по уровню, затем по severity).
- Появляется, только если ошибка держится > 0,7 с — никакого мигания.
- Смена подсказки не чаще раза в 1 с (гистерезис).
- Палец из подсказки подсвечивается на скелете и на призрачной руке.
- Тексты — по `hintCode` из `strings.ru.ts`, формулировка всегда «что сделать»,
  а не «что не так»: «Согни безымянный палец», а не «Безымянный палец неверный».
- Каждая показанная подсказка пишется в статистику: `{ letter, hintCode, timestamp }` →
  экран итогов и «повтори слабые буквы».

### 9.3 Демо твиста
Сценарий должен провоцировать ошибку естественно: первые буквы урока выбираются так, чтобы
частая ошибка (не тот палец) была вероятной. Подсказка должна появиться у судьи сама.

## 10. Экраны

Приоритеты: **P0** — без этого нет продукта; **P1** — делаем; **P2** — если останется время.

### 10.1 Welcome (P0)
- Название, одна фраза о продукте, одна кнопка «Включить камеру» (единственный клик мышью).
- Понятные ошибки: камера запрещена / не найдена / занята — с инструкцией, а не белый экран.
- Индикатор загрузки модели MediaPipe.

### 10.2 ControlTutorial — обучение управлению (P0)
4 шага по ~7 с, каждый с анимированной иконкой и подсказками режима «ошибка»:
1. «Наведи указательный палец на кружок» — курсор-палец.
2. «Сделай щипок, чтобы нажать» — щипок по мишени.
3. «Покажи большой палец вверх» — ОК.
4. «Покажи открытую ладонь» — назад.
После 4 шагов — «Готово! Теперь ты управляешь руками» → карта уроков.
Кнопка «Пропустить» (щипок/задержка) для повторных запусков.

### 10.3 LevelMap — карта уроков (P1; в P0 — простой список уроков)
- Уроки по 3–4 буквы, следующий открывается после прохождения текущего.
- На уроке — звёзды (0–3), на шапке — общий XP.
- Кнопки: урок, «Мост», «Повтори слабые буквы» (P1).

### 10.4 Lesson — урок (P0)
- Раскладка на ноутбуке: камера ~60% слева, справа карточка буквы + подсказка;
  на телефоне — вертикально: камера сверху, карточка снизу.
- Поверх камеры: скелет, призрачная рука (P1), подсветка пальцев, `HintBanner`.
- Буква засчитана → звук, конфетти, +XP, звёзды → следующая буква.
- Звёзды за букву: 3 — без подсказок, 2 — одна подсказка, 1 — две и больше.
- Выход — открытая ладонь 1,5 с.

### 10.5 Bridge — «Мост» (P1)
- «Напиши слово жестами»: слово из `words.ts` (только из выученных букв) или имя.
- Пользователь показывает буквы по очереди, распознанные появляются крупно на экране.
- Слово собрано → озвучка через TTS + анимация. Если `speechSynthesis` недоступен или нет
  голоса `ru-RU` — только текст, без ошибок.
- Режим «ошибка» работает и здесь.

### 10.6 Results — итоги (P0)
- Буквы урока, точность, число подсказок, самые частые ошибки, XP, звёзды.
- Кнопки: «Дальше», «Повторить», «На карту».

### 10.7 Прогресс (P1)
- В localStorage: открытые уроки, звёзды по буквам, XP, статистика ошибок.
- Кнопка «Сбросить прогресс» (с подтверждением).
- Локальная таблица рекордов в «Мосте» (P2).

### 10.8 /record — служебная страница (P0)
- Не видна в меню, открывается по адресу `/record`.
- Выбрать букву и имя записывающего → обратный отсчёт 3 с → запись 50–100 кадров
  нормализованных точек → превью → экспорт JSON.
- Отдельная кнопка «Сохранить эталон» — один лучший кадр для призрачной руки.
- Формат образца:
```json
{ "letter": "А", "signer": "S01", "handedness": "Right",
  "frames": [[x0, y0, z0, x1, y1, z1, "... 63 числа"]] }
```

## 11. Геймификация (лёгкая)

Делаем: карта уроков, звёзды, XP, конфетти и звуки, «повтори слабые буквы».
НЕ делаем: стрики, лиги, напоминания, жизни/сердечки, регистрацию, аккаунты.
Геймификация обрамляет главную фишку (камера поправляет руку), а не заменяет её.

## 12. Нефункциональные требования

- FPS: ≥ 20 на ноутбуке, ≥ 12 на телефоне. Счётчик FPS — в режиме отладки (`?debug=1`).
- Отклик на жест < 300 мс; первая загрузка < 5 с.
- Браузеры: Chrome, Edge, Safari (включая iOS Safari). Firefox — по возможности.
- Мобильная вертикальная раскладка, фронтальная камера.
- Тексты — на русском, все в `strings.ru.ts` (задел под казахский).
- Доступность: высокий контраст, крупный шрифт, сообщения не только цветом
  (иконка + текст), звук можно выключить.

## 14. Код и качество

- TypeScript strict, без `any` без причины.
- `recognition/` покрыт юнит-тестами на синтетических точках: нормализация, углы,
  состояния пальцев, щипок с гистерезисом, правила букв, hintEngine (задержка и гистерезис).
- Цикл распознавания — через `requestAnimationFrame`, без лишних ре-рендеров React:
  точки и курсор рисуются на canvas, в React-состояние идут только события
  (клик, буква засчитана, подсказка сменилась).
- Коммиты маленькие и осмысленные, Conventional Commits (`feat:`, `fix:`, `refactor:`).
  История коммитов проверяется жюри.

## 17. Фазы

После каждой фазы: `npm run build`, `npm test`, краткий отчёт (что сделано, как проверить,
какие пороги стоит подстроить), предложение коммитов — и СТОП.

0. **Каркас.** Vite + React + TS, структура папок, линтер, Vitest, `strings.ru.ts`,
   конфиг Vercel. Пустые экраны с роутингом.
1. **Камера и трекинг.** Welcome с обработкой ошибок камеры, HandLandmarker, скелет на canvas,
   `HandStatus`, `?debug=1` с FPS. Проверить на телефоне через деплой.
2. **Нормализация и признаки.** `normalize`, `features`, `smoothing` + тесты.
   Страница `/record` с экспортом образцов и эталона.
3. **Слой управления.** Курсор-палец, щипок, клик задержкой, позы-команды, `GestureButton`,
   `HoldRing`, `GestureLegend`, `gestureContext`. Все кнопки приложения работают руками.
4. **Обучение управлению.** ControlTutorial из 4 шагов с подсказками режима «ошибка»
   для управляющих жестов.
5. **Буквы и режим «ошибка».** `rules`, `frameChecks`, `hintEngine`, экран Lesson
   с 2–3 буквами-заглушками, подсветка пальцев, засчитывание с удержанием.
   Экран Results. **После этой фазы должен работать полный P0-сценарий.**
6. **kNN и призрачная рука.** `knn`, `classifier`, `ghost`, `GhostHand`.
7. **Карта уроков и геймификация.** LevelMap, звёзды, XP, прогресс в localStorage,
   конфетти, звуки, «повтори слабые буквы».
8. **Мост.** Экран Bridge, сборка слова, TTS с фолбэком.
9. **Полировка.** Мобильная раскладка, доступность, обработка краевых случаев,
   README, финальная проверка по чек-листу.
