# Подключение распознавания РЖЯ

Статус: интерфейс готов, реального распознавателя и профилей ошибок в репозитории пока нет. `main.tsx` создаёт `SignBridgeApp` без адаптера. Ни один клик демо не анализирует видео.

## Контракт с фронтендом

`RecognitionAdapter` из `src/signbridge/adapter.ts` получает элемент `video`, документированный словарь, `onFrame` и `onError`. `start` синхронно возвращает функцию остановки. Загрузку модели можно делать асинхронно внутри адаптера, но остановка должна быть доступна немедленно и отменять незавершённую загрузку/циклы/worker.

```tsx
<SignBridgeApp dictionary={verifiedDictionary} adapter={localRslAdapter} />
```

Это точка интеграции, а не существующие переменные в репозитории. Реализацию пишет разработчик распознавания. Адаптер не должен запрашивать новую камеру: поток уже принадлежит `useCamera`.

| Поле события `RecognitionFrame` | Назначение                                                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `id`, `timestamp`               | Идентификатор и время кадра                                                                                               |
| `source`                        | Адаптер камеры принудительно устанавливает `camera`; `demo` возможен только в ручной панели                               |
| `status`                        | `idle`, `tracking`, `almost`, `recognized`, `uncertain`                                                                   |
| `landmarks`                     | 21 точка основной кисти; нормированные `x,y` в диапазоне 0–1 исходного, незеркального видео                               |
| `secondaryLandmarks`            | Необязательная вторая кисть, также 21 точка; стабильный порядок кистей на всём жесте                                      |
| `candidates`                    | Уникальные идентификаторы классов и score 0–1; передавать минимум двух конкурентов, включая вне-словарные/фоновые классы  |
| `corrections`                   | Причина, конкретная инструкция, номера суставов, целевая кисть и необязательная стрелка                                   |
| `holdProgress`                  | Подтверждение жеста от 0 до 1; для динамического жеста это завершение всей последовательности, а не фиксация одного кадра |
| `eventId`                       | Непустой уникальный идентификатор одного завершённого жеста; одинаковый для повторных кадров этого события                |

`corrections[0]` отображается как приоритетная подсказка. Её `hand` принимает `primary` или `secondary`; по умолчанию `primary`. `arrow.from/to` используют те же координаты видео. SVG учитывает `object-fit: contain`, пропорции видео и зеркальный просмотр: адаптер не зеркалит точки самостоятельно. `z` допускается, но не служит измерением сантиметров.

Словарь `DictionaryEntry` содержит `id`, `phrase`, `gloss`, `category`, `note`, `verified`, `reference`. Верифицированная запись должна иметь проверенный класс и источник. Все пять встроенных макетов имеют `verified: false`, поэтому камера не сможет принять их как проверенные жесты.

## Границы приёма

1. Валидировать координаты и оценку модели. Неполная кисть не становится зелёной.
2. Убедиться, что победивший класс входит в словарь. Не удалять неизвестный победивший класс ради следующего известного.
3. Проверить уверенность и отрыв от второго кандидата. Предварительно: 0.65 и 0.12; это не откалиброванные вероятности.
4. Для `almost` нужна достоверная цель и валидная конкретная коррекция. Если её нет, показать нейтральное состояние без произвольных стрелок.
5. Для `recognized` нужны `verified: true`, завершение жеста и `eventId`. Фронтенд добавляет/озвучивает одно сообщение на событие.
6. Новое событие одного класса создаётся после отпускания/завершения предыдущего жеста и нового исполнения. Генерация нового `eventId` на каждом кадре приведёт к спаму, поэтому сегментация принадлежит распознавателю.

UI фильтрация страхует интеграцию, но не заменяет оценку качества модели. РЖЯ может включать две руки, положение относительно тела, движение и немануальные компоненты: один открытый скелет не описывает весь язык.

## Источники и выбор MVP

[Slovo](https://github.com/ai-forever/slovo) содержит видео жестов-слов и подготовленные landmarks рук. [Bukva](https://github.com/ai-forever/bukva) предназначен для русской дактильной азбуки, в том числе динамических знаков. Для первой версии коммуникации выбрать 3–5 классов Slovo после просмотра аннотаций и исполнения. Не утверждать, что пять желаемых фраз автоматически соответствуют пяти классам.

Предобученные модели этих проектов анализируют последовательности видеокадров. Наличие ONNX-весов не гарантирует совместимость с браузером, скорость на телефоне или возможность получить ошибки пальцев. Проверить отдельно операторы, входной формат, время загрузки и память. Если выбрать собственную компактную модель по landmarks, обучить и проверить именно её, сохраняя разделение по исполнителям.

## Собственная диагностика ошибок

Для каждого ограниченного жеста нужен проверенный профиль: допустимая форма пальцев, ориентация ладони, расположение относительно тела, траектория и временные фазы. Landmarks нормировать относительно размера кисти и положения человека, сохраняя информативные признаки и различия между классами. Диапазоны задавать по нескольким исполнителям, а не одному идеальному кадру.

Классификатор выбирает намерение. Отдельный диагностический слой сравнивает наблюдение с профилем ближайшего достоверного класса, выбирает одну наиболее полезную поправку и формирует `Correction`. Последовательность движения оценивать по временным данным. Для скрытого пальца/плохого кадра дать инструкцию улучшить видимость, не выдавать анатомическую ошибку без доказательств.

Пример UX: «Почти. Подними ладонь к отметке и удерживай положение 0,5 с» + стрелка вверх. Измеренные «6–8 см» возможны только после отдельной метрической калибровки с известным масштабом; текущая ручная подготовка этого не делает.

## Готовность к сдаче

- Минимум три реально распознанных жеста и явные действия приложения.
- Правильные, неправильные, близкие и неизвестные жесты от разных людей; отдельная проверочная выборка.
- Нет повторных сообщений при длительном показе жеста.
- Подсказка соответствует наблюдаемой ошибке и принятому классу; неоднозначный жест не превращается в случайное намерение.
- Проверка двух кистей, зеркала и задней камеры; изменение кадра/освещения.
- Локальная обработка без передачи видеопотока; inference в worker, чтобы интерфейс оставался отзывчивым.
- Завершённый путь от запуска до результата без мыши/клавиатуры после системного разрешения камеры.
- Документированные видеообразцы, атрибуция и условия использования источников.
- HTTPS-деплой и воспроизводимый запуск; измеренная скорость на настоящем телефоне.
